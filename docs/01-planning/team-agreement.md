# Рабочее соглашение команды

## Состав команды

Команда состоит из одного человека. Все роли выполняет участник А.

| Роль | Зона ответственности |
|---|---|
| Участник А | Все задачи ЛР1–ЛР4 |

## Время синхронизации

Ежедневная саморефлексия продолжительностью 10 минут: что сделано, что мешает, следующий шаг.

## Каналы связи

- GitHub Issues — для фиксации задач и обсуждений.
- GitHub Projects — для ведения доски.
- Локальные заметки — для промежуточных записей.

## Правила ревью

Каждое изменение проходит самопроверку по чек-листу:
- Соответствие критериям приёмки.
- Отсутствие очевидных ошибок.
- Прохождение конвейера CI.

## Разрешение разногласий

При конфликте приоритетов решение принимается по значениям WSJF и критериям приёмки.

## Ветвление и коммиты

- Основная ветка: main.
- Ветка задачи: feature/<issue-id>-<slug>.
- Формат сообщений коммита: Conventional Commits (feat, fix, docs, chore, refactor, test).
