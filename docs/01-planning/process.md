# Процесс команды

## Методология

Выбрана методология Kanban.

Обоснование:
- Команда состоит из одного человека, церемонии Scrum избыточны.
- Поток задач неравномерный, важна гибкость в приоритетах.
- WIP-лимиты позволяют удерживать фокус на одной задаче.

## Доска задач

| Колонка | WIP-лимит | Обоснование |
|---|---|---|
| Бэклог | — | Без ограничения |
| Готово к работе | 3 | Соответствует DoR |
| В работе | 1 | Закон Литтла: L = λW, при λ ≈ 1 задача/нед и W ≈ 1 нед → L = 1 |
| Ревью | 1 | Самопроверка перед слиянием |
| Готово | — | Соответствует DoD |

Закон Литтла: количество задач в системе (L) равно интенсивности поступления (λ), умноженной на среднее время пребывания (W). При интенсивности одна задача в неделю и времени выполнения одна неделя оптимальный WIP равен единице.

## Definition of Ready

История готова к работе, если:
- Соответствует INVEST.
- Содержит не менее двух критериев приёмки в формате Дано / Когда / Тогда.
- Оценена в story points.
- Зависимости выявлены и учтены.

## Definition of Done

История считается выполненной, если:
- Код влит в основную ветку через pull request.
- Конвейер CI завершился успешно.
- Ручной тест сценария пройден.
- Документация обновлена.
- Задача закрыта в трекере.

## Ветвление

- Основная ветка: main.
- Ветки задач: feature/<issue-id>-<slug>.
- Каждое изменение связано с issue.
