# Отчёт о непрерывной доставке (CD)

## Выбранное решение

Для автоматического деплоя выбран сервис **Render.com**.

Причина выбора:
- Нативная поддержка Docker.
- Автоматический деплой из GitHub при мерже в `main`.
- Бесплатный тариф для учебных проектов.

## Конфигурация

Создан файл `render.yaml` (Infrastructure as Code), который описывает:
- Тип сервиса: Web Service (Docker).
- Использование `Dockerfile` из репозитория.
- Переменную окружения `DATABASE_URL`.

В `src/db.py` добавлена поддержка переменной окружения `DATABASE_URL`:

    DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./study_tracker.db")

**Важное ограничение:** на бесплатном тарифе Render постоянные диски (Persistent Disks) недоступны. База данных SQLite размещена на эфемерном диске и сбрасывается при перезапуске контейнера. Для учебного MVP это допустимо. При необходимости production-хранения рекомендуется миграция на Render Postgres.

## Процесс доставки

1. Разработчик создаёт PR.
2. GitHub Actions запускает CI (линтер, тесты, покрытие).
3. При мерже PR в `main` Render автоматически замечает новый коммит.
4. Render пересобирает Docker-образ и обновляет сервис без простоя.
