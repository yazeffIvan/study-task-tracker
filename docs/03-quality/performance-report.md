# Отчёт о производительности

## Методика тестирования

- Инструмент: Locust 2.46.7.
- Сценарий: имитация 10 одновременных пользователей, которые просматривают курсы, открывают карточки и создают новые курсы.
- Длительность: 30 секунд.

## Замер «До» (Baseline)

| Метрика | Значение |
|---|---|
| Общий RPS | 5.28 |
| Avg (общее время) | 8 мс |
| POST /courses (Avg / Max) | 41 мс / 131 мс |
| GET /courses (Avg / Max) | 7 мс / 14 мс |
| Ошибки | 0% |

**Выявленное узкое место:** Операция записи `POST /courses` занимает значительно больше времени (41 мс), чем чтение (7 мс). При одновременной записи SQLite блокирует базу данных, что приводит к пиковым задержкам до 131 мс.

## Оптимизация

1. **Добавлены индексы в БД** (`src/models.py`). Индексы на поля `Course.created_at` и `Task.deadline` ускоряют сортировку и фильтрацию записей.
2. Попытка включить WAL-режим в SQLite дала отрицательный результат (замедлила чтение), поэтому была отменена.

## Замер «После» (After)

| Метрика | Значение | Изменение |
|---|---|---|
| Общий RPS | 4.89 | Без изменений |
| Avg (общее время) | 10 мс | Без изменений |
| POST /courses (Avg / Max) | 35 мс / 71 мс | **Улучшение в 1.8 раза** |
| GET /courses (Avg / Max) | 10 мс / 15 мс | Без изменений |
| Ошибки | 0.69% (1 запрос 404) | Артефакт теста |

## Выводы

Добавление индексов позволило **сократить максимальное время создания курса с 131 мс до 71 мс** (почти в 2 раза). 
Пропускная способность сервиса составляет около **5 запросов в секунду при 10 пользователях**, что более чем достаточно для MVP-трекера. 
Дальнейшее масштабирование (переход на PostgreSQL, асинхронный драйвер БД) выходит за рамки задач MVP.
