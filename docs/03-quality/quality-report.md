# Отчёт о качестве кода

## Цель

Зафиксировать текущее состояние тестирования, настроить порог качества в CI и выявить технический долг.

## Инструменты

- **pytest** — фреймворк для тестов.
- **pytest-cov** — плагин для замера покрытия.
- **ruff** — линтер для проверки стиля и потенциальных ошибок.

## Текущее покрытие

На момент составления отчёта написано **17 тестов**. Покрытие составляет **100%** по всем модулям.

| Модуль | Покрытие |
|---|---|
| `src/__init__.py` | 100% |
| `src/db.py` | 100% |
| `src/main.py` | 100% |
| `src/models.py` | 100% |

## Настройка порога в CI

В файл `.github/workflows/ci.yml` добавлен запуск тестов с флагом `--cov-fail-under=95`. 
Это означает, что **любой pull request, который снизит покрытие ниже 95%, не сможет быть смержен**, так как CI завершится с ошибкой.

## Выявленный технический долг и его устранение

### 1. Неиспользуемый файл схем (устранено)
При замере покрытия выяснилось, что `src/schemas.py` имеет 0% покрытия. Анализ показал, что валидация данных выполняется вручную в `src/main.py`, а Pydantic-схемы не используются.
**Решение:** файл `src/schemas.py` удалён. Это уменьшило количество мёртвого кода и повысило общее покрытие до 100%.

### 2. Заглушка в счётчике заданий (устранено в ЛР3)
В ЛР2 в списке курсов выводился жёстко закодированный `0` в колонке «Заданий». В ЛР3 при реализации US-5 и US-6 счётчик был заменён на реальный `{{ course.tasks | length }}`.

## Выводы

Код сервиса полностью покрыт тестами. Настроен автоматический контроль качества: любые изменения, снижающие покрытие, будут заблокированы на уровне CI.
